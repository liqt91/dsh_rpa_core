架构特点：一条命令 = 一个 manifest，贯穿三层

每条命令是一个 JSON 清单，声明 input_schema、output_schema、x-outputs（输出别名）、x-depends（字段联动）、kind/effect（副作用契约）、errors、default_timeout_seconds。这份清单同时被三层消费：

  • 编辑器：按 schema 生成表单，按 x-depends 动态显隐字段，按 x-outputs 渲染「保存到变量」输入框
  • 编译器：静态校验 ${} 引用合法性，拦截前向引用与未声明变量
  • 运行时：分派 executor，递归解析全部 inputs 中的变量，输出写入 scopes

变量体系

用户在节点上给输出起别名（如「保存网页对象到 web_page1」），运行时把该节点输出写入 scopes["variables"]["web_page1"]，下游用 ${web_page1.sessionId} 引用。引用根共 5 类：inputs（流程入参）、variables（用户别名）、steps（步骤输出）、loop（循环项）、error（异常对象）。

二、做得好的地方

  • 渐进式披露到位：参数数最多 10 个（打开网页），但必填仅 1 个（url）；必填中位数 2 个。默认参数大量内置，新手不被表单淹没，专家可展开调参。
  • manifest 单一事实源：字段联动（x-depends）与输出别名（x-outputs）声明在清单里，新增命令无需改前端代码即可获得自适应表单。
  • 按意图而非实现分组：指令面板分「页面导航 / 元素操作 / 数据处理 / 桌面会话 / 桌面窗口 / 桌面控件」，用户按「我要做什么」找，而非按技术前缀。
  • 输出别名是关键的思维跃迁：把「第 3 步的 sessionId 输出」转译为「web_page1 这个网页对象」，对齐影刀心智模型，流程可读性显著提升。
  • 错误前置到编译期：引用未声明变量、前向引用在运行前就被拦截，而不是跑到一半才炸。

三、问题清单（按严重度）

P0 变量能力已实现，但界面几乎不暴露

运行时对所有 54 条命令的全部字段无差别递归解析 ${}，但编辑器只在极少数字段提示「可以填变量」。

实测：字段级 x-fx 仅 3 个（browser.input 的 selector/text、browser.navigate 的 url）；命令级 x-fx = 0 条。而 Vue 版 PropsPanel 读的正是命令级数组 manifest['x-fx'] → 新版编辑器的 fx 按钮永远不会出现（迁移引入的回归）。

后果：51 条命令里用户其实都能填 ${web_page1.sessionId}，运行时也能正确解析，但界面没有任何按钮、提示或补全引导——能力存在却无人知晓。

P0 不支持字符串插值，且静默失败

引用语法要求整串完全匹配 ${...}，不支持「文本 + 变量」拼接——而这恰恰是高频需求（拼文件名、URL、消息文案）。

# 实测结果（resolver.resolve）
'${web_page1.sessionId}'        -> 'S1'                    # 正常
'订单${inputs.kw}已处理'         -> '订单${inputs.kw}已处理'  # 原样返回，不报错
'前缀-${inputs.kw}'             -> '前缀-${inputs.kw}'      # 原样返回，不报错
'${web_page1.missing}'          -> ERROR: Unknown reference
'${unknownVar}'                 -> ERROR: Unknown reference

后果：用户写 订单${orderId}已处理，流程不报错、不警告，原样把字面量写进文件或输入框。这是最难排查的失败类型——静默错误。影刀、UiPath 等工具均支持文本内插值。

P1 sessionId 管道负担：83% 的命令都要填

45/54 条命令强制要求 sessionId，意味着每个节点都要重复声明「作用于哪个网页 / 窗口」。虽然编辑器已用下拉自动引用别名减轻负担，但用户仍必须先建立「会话对象」这个抽象概念。

对比：影刀在「打开网页」后，后续指令默认作用于当前激活网页，无需逐条指定。
建议：支持「默认会话」——sessionId 省略时自动使用最近激活的会话，可消除大部分重复填写，同时保留显式指定能力。

P1 错误码未中文化，且缺少修复建议

共 12 种错误码（ELEMENT_NOT_FOUND、SESSION_LOST、ELEMENT_AMBIGUOUS 等），但 i18n 中无中文映射——编辑器界面已全面中文化，唯独运行错误直接抛英文码，体验断裂。

建议：错误码配中文文案 + 可操作建议。例如 ELEMENT_NOT_FOUND 应提示「选择器未命中元素：请确认页面已加载完成，或重新捕获该元素」。

P2 双后端命名向用户暴露技术细节

desktop.attachWindow（UIA）与 desktop.win32.attachWindow（Win32）并列，中文名「附着窗口（UIA）」。业务用户不理解 UIA / Win32 的差异，却被要求做技术选型。

建议：默认提供「附着窗口」自动选后端（UIA 优先、失败降级 Win32），后端选择收进高级选项。

P2 语义分组硬编码维护，新命令会掉队

分组规则是 app.js 里的 id 白名单数组，新增命令需手动改代码，否则掉进「按 id 前缀兜底」的组里，体验割裂；「桌面控件」组还依赖排除法判定，较为脆弱。

建议：把分组下沉为 manifest 的 x-group 字段，命令与分类同处一处，与「单一事实源」原则一致。

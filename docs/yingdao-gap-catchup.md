## 2. 本轮外部核查的新事实（官方文档，2026-09-28）

1. **锚点（v5.22+）有完整的自动推荐规则**：输入框/下拉框找**左侧与上方**、动态文本找**周围**、
   按钮找**内部**、单选/复选框找**右侧与下方**；「无法百分之百确定或发现重复项则不自动添加」。
   手动添加 = 编辑器里 Ctrl+单击指定；运行语义 =「**先到锚点**，从而定位目标元素」（相对定位）。
   ⇒ 我方若做，自动推荐可以砍成「仅提示、不自动加」起步，手动 Ctrl+单击与运行期消费才是本体。
2. **「修复元素」= AI 属性生成 + 引用处自动更新**：未找到时重新指出元素，AI「根据新旧元素属性
   关系生成更稳定的属性」；且「修复完成后流程里引用这个元素的地方**会自动更新**」。
   ⇒ 这条体验**以引用语义为前提**——正是 §8.4-②（我方值拷贝）缺的地基。不做 ②，修复永远只能
   改资产不改指令。
3. **「AI 辅助定位」是运行期兜底，不只是捕获期优化**：「主要作用在**元素找不到时**，作为以上几种
   定位方式的兜底，通过图像和语义描述定位」。⇒ 与我方运行期自愈是**同一层**的东西：可设计成
   候选回退之后的**第三级自愈**（candidates → 兜底匹配 → AI 语义兜底），而不是并行的「AI 功能」。
4. **相似元素是「成组 + 循环指令」闭环**：捕获 1 个 → 点「捕获相似元素」→ 选第 2 个 → 系统识别
   成组（界面闪烁）→ 配「循环相似元素」指令批量操作。⇒ 相似元素不是编辑器单点，而是**数据模型
   （成组）+ 捕获交互（二样本）+ 指令面（循环）**三件套。
5. **元素库批量验证**（第三方实操文，与截图一致）：元素库全选 → 右键「验证」→ 在当前页面逐个
   找、飘红标失效。⇒ 属**活体批量**，依赖会话保活（P3），离线侧只能做结构校验（死字段/唯一性）。
6. **矩阵外新缺口：「父子元素」捕获**（四种捕获方式之一：通过父元素定位子元素）。§9.3 的 15 项
   没有它。定性：与锚点同属「相对定位」家族，模型层同款新字段可一并覆盖。

### 我方领先（对标时别丢，§8.5 + 本轮补强）

1. **运行期自动自愈** vs 影刀「人发现→点修复」；且主定位命中但预检不过**不重试**（换候选=换元素点，更保守）。
2. 影刀「修复元素」要 **AI + 手动重指**；我方候选按序回退是**无人值守**的。E2 做了之后是把
   「候选穷尽后的最后一跳」也自动化，叙事上完全顺接。
3. 捕获确认框就给候选 + 实测命中数（影刀无候选概念）；17 个只读标签含 `accessibleName`/`label`。
4. locator 字段集按 backend 分 + **死字段保存前拦截**（影刀 XPath 一把梭，写错即失效）。
5. 混合单入口（网页/桌面不用先选）；三级错误码；多手势 + Esc 取消。

# GUI 运行控制：运行 / 暂停 / 继续 / 取消 / 恢复

适用：`rpa-core gui`（PySide6 编辑器，ADR 0016 的主力形态）。
相关决策：ADR 0005（暂停与继续）、ADR 0004（检查点与恢复）、ADR 0011（运行控制 proxy）、M21。

## 五个动作

| 动作 | 入口 | 语义 | 生效点 |
|---|---|---|---|
| **运行** | 工具栏「运行」 | spawn `rpa-core run` 子进程 | 立即 |
| **暂停** | 工具栏/悬浮窗「暂停」 | 写控制文件请求暂停 | **下一个节点边界** |
| **继续** | 工具栏/悬浮窗「继续」 | 见下节（两种处境一个按钮） | — |
| **取消** | 工具栏/悬浮窗「取消运行」 | 终止子进程 | 立即 |
| **恢复** | 「继续」+ 确认框 | 从检查点起新进程续跑 | 确认后 |

优先级：**取消 > 暂停 > 超时**（ADR 0005）。同时请求取消与暂停，终态是 `cancelled`。

## 暂停不是"立即停"

暂停请求送达后，**进行中的命令会自然跑完**（暂停不打断、不取消任何已开始的命令），
run 走到下一个 action 入口才停下。停下时把 `status=paused` 连同最终检查点一起落盘。

由此有三个必然行为，都不是 bug：

- 刚点暂停时界面显示「已请求暂停…」——此时还没停。
- 长耗时步骤（如 30s 超时命令）会推迟暂停落地。要立刻停请用「取消」。
- 若请求送达时剩余节点已全部跑完，run 正常 `succeeded`，暂停不落位。

## 「继续」为什么一个按钮管两件事

同一个按钮按 run 的处境分两种：

- **run 还在跑**（暂停请求尚未落地）→ **撤销请求**。run 照常往下跑，不会停。
  这是必要的反悔通道：否则误点暂停后只能取消重跑。
- **run 已收口为 `paused`**（子进程已退出）→ **起新进程从检查点续跑**。
  「暂停即收口」是 ADR 0005 的既定语义：暂停后进程退出、不占资源、证据可查证，
  代价是「继续」是一次新的 `rpa-core resume`，而不是在原进程里接着跑。

续跑**不会重复执行已完成的节点**（从检查点跳过），事件流也不会把历史事件重放一遍。

## 会话续接：浏览器能续，桌面不能

| 通道 | 会话是什么 | 续跑后 |
|---|---|---|
| **浏览器**（扩展单通道） | 用户真实浏览器里的**标签页句柄**（`tabId`），不随 run 进程退出而消失 | ✅ 按检查点重建 `sessionId → tabId`，接着操作暂停前那批标签页 |
| **桌面**（`desktop.uia` / `desktop.win32`） | 进程内的 pywinauto 对象 | ❌ 旧 `sessionId` 会以 `SESSION_NOT_FOUND` 失败，需重新 launch |

也就是说：含 `browser.*` 的流程可以放心暂停/继续；含桌面会话的流程暂停后「继续」大概率
需要在续跑里重新 launch，或干脆用「取消」重跑。

真机验证（2026-09-19，macOS + Edge 153 + 扩展 0.3.1）：`browser.navigate` → 暂停 →
`resume` 后同一个 `sessionId` 仍能操作原标签页（`reload` 成功、`getText` 命中元素），
已完成节点未重跑。

## 需要人工确认的两种终态

run 收口后，若终态是下面两种，点「继续」会**先弹确认框**（默认按钮是「不恢复」）：

| 终态 | 含义 | 恢复前的确认点 |
|---|---|---|
| `indeterminate` | 某步骤的外部写入结果**未知** | 确认勾选后带 `--allow-indeterminate` 恢复；**副作用可能重复发生** |
| `recovery_required` | 写检查点失败，进度快照可能落后 | 可能**重放最后一个步骤** |

默认拒绝是硬约束（ADR 0004 第 4 道门）：不确定副作用是否已发生，就不要自动重跑。
「暂停后继续」（`paused`）没有这个门槛——暂停点与崩溃点不同，它是干净的边界。

## 相关文件

| 路径 | 内容 |
|---|---|
| `<artifacts>/<run_id>/result.json` | 终态（`paused` 也在这里） |
| `<artifacts>/<run_id>/checkpoint.json` | 续跑依据（含 `sessionId` / `tabId`） |
| `<artifacts>/<run_id>/control.json` | 跨进程暂停开关（GUI/CLI 写，run 子进程读） |

## 已知边界

- **关闭 GUI 不影响已暂停的 run**：进程已经收口，之后可用 CLI
  `rpa-core resume <workflow> --run-id <uuid>` 继续。
- **Web 编辑器（`rpa-core devserver`）尚未前端化暂停/继续**：本期只做了 PySide6 GUI。
  其 HTTP 端点也未加（ADR 0006 的通道对齐要求记在 M21 的后续项里）。
- **桌面会话不跨进程**（见上表），这是 ADR 0004 的既有约定，M21 未改动。

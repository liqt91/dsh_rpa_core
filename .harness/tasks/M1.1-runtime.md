# M1.1 Runtime 正确性

状态：`done`

## 目标

确保每种失败、超时、重试、取消和证据写入失败都能产生稳定的终态结果，并且不会遗留 executor 任务。

## 任务

- [x] 将 resolver 失败映射为 `INVALID_REFERENCE`。
- [x] 将输入 Schema 失败分类为 `INVALID_INPUT`。
- [x] 为 executor 输出违反契约新增 `INVALID_OUTPUT`。
- [x] 为步骤错误附加 `nodeId`、`commandId` 和 `attempt` 上下文。
- [x] action 超时后取消并等待 executor task 结束。
- [x] workflow 超时传递到正在运行的 executor，并确保没有活动任务遗留。
- [x] Python worker 子进程超时或取消时先 terminate，必要时再 kill。
- [x] 定义有界重试退避，并为每次 attempt 记录事件。
- [x] 确保所有重试不超过 workflow 总 deadline。
- [x] 传播事件和终态结果持久化失败，禁止报告假成功。
- [x] 为所有失败路径增加针对性的单元测试和契约测试。

## 验收标准

- [x] 所有已测试失败都有稳定错误码和步骤上下文。
- [x] 超时或取消后没有 executor task 或子进程遗留。
- [x] 仅在 `retryable=true` 时重试，并且不超过 workflow deadline。
- [x] 证据持久化失败不会产生成功的运行结果。
- [x] 原有 Chromium E2E 保持通过。
- [x] `uv run python .harness/scripts/check_all.py` 通过。

## 范围外

- 持久化检查点和崩溃恢复。
- 暂停和继续。
- 分布式 worker 或任务队列。
- 除非基准测试证明有必要，否则不做事件批量写入。
- API、UI、DSH、MCP、调度器和安装器。

## 已确定决策

- 持久化失败抛出 `RunPersistenceError`。终态提交失败时，异常携带内存中的失败 `RunResult`；证据不完整时，调用方绝不会收到成功结果。
- 重试使用 action 可配置的有界指数退避，并受 workflow deadline 约束。
- Executor 必须传播 task cancellation，并在 `execute()` 返回前释放本次 attempt 拥有的资源。
- 浏览器 session 的整轮运行所有权属于 M1.2 的副作用和资源生命周期议题。M1.1 保证活动 attempt 被清理，但不会隐式关闭共享 registry。

- 24 项测试通过，其中包含 Chromium E2E。
- Runtime 测试覆盖引用、输入、输出错误分类，步骤上下文，step/workflow 超时清理，重试资格、重试事件、deadline 耗尽和持久化失败。
- Python worker 契约测试验证 terminate、宽限超时、kill、进程回收、通信任务清理，以及活动进程计数归零。
- Ruff、架构检查、任务一致性检查和完整 harness 门禁全部通过。

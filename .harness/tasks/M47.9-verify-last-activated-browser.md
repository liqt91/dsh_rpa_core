# M47.9：校验目标改用「最近激活的浏览器」（对齐影刀）

Status: `done`

Plan: M47 活体校验通道 / 真机反馈「校验时该弹哪个浏览器」

## 目标

M47.8 把「两个浏览器都闪框」修成了「非前台不闪框」，但代价是引入**新回归面**：
点「校验元素」时前台是**我们的对话框**（`present_window(always_on_top=True)` + `raise_()` +
`activateWindow()` 抢焦），Chrome / Edge 两个浏览器**都判非前台** ⇒ `silent:true` ⇒
**都不闪框**。用户最期待的「点校验就看当前页命中」直接失效。

维护者口径（=规格）：

> *影刀在校验的时候只看哪个浏览器是**最后被激活的**。如果对话框的上一个激活窗口不是浏览器，
> 他会让浏览器到前台来。比如我点击 edge、chrome、资源管理器，再点校验元素，
> 影刀会将 chrome 前置，然后在上面高亮元素。*

即：**取「最近被激活的浏览器」**（非浏览器窗口被跳过），并**把它置前**再高亮。

## 关键发现：系统已有这个「栈」，不用自己维护

实测（只读探针，本机真窗口）确认 **Windows Z 序 == 窗口激活栈**：

- `GetTopWindow(NULL)` = 栈顶（最靠前 / 最近激活）；
- `GetWindow(hwnd, GW_HWNDNEXT)` 沿链向下 = 由近到远的激活顺序；
- `EnumWindows` 返回与之**同序**（实测前 12 个逐一致）。

⇒ **「最近被激活的浏览器」= Z 序链里第一个浏览器类窗口**，非浏览器窗口（资源管理器、
我们自己的对话框、系统提示窗）自然被跳过。**无轮询、无跨进程时钟、无竞态。**

与「扩展自报 `focusedAt`」方案比：Z 序**能看见非浏览器窗口**（资源管理器夹在中间正是
维护者例子的要害），扩展自报看不见；且 Z 序是系统维护的，不用 host 起轮询线程。

## 实测必须做的过滤（都踩到过）

- **`GetTopWindow` 第一项可能不是用户窗口**：实测栈顶是 `tooltips_class32` 空提示窗 ⇒
  逐项过滤 `IsWindowVisible` 且标题非空 且无 `WS_EX_TOOLWINDOW(0x80)`。
- **Z 序链可达 400+ 项**（QQ 拼音/IME/工具提示密布），真实用户窗口排在 100~200 位 ⇒
  枚举上限必须够大（取 **2048**）。初版 `seen < 64` 只枚举到 13 个、漏掉所有浏览器。
- **浏览器判定只看进程名**：`Chrome_WidgetWin_1` 类名被 Chrome / Edge **以及**定制 Chromium
  客户端（实测 `咚咚.exe` / `WorkBuddy.exe`）共用 ⇒ 只看类名会把定制客户端误判成浏览器
  （排在真 Edge 之前导致取错）。必须 `GetWindowThreadProcessId` + `QueryFullProcessImageNameW`
  拿进程名，命中已知表（`msedge.exe`/`chrome.exe`/`brave.exe`/`opera.exe`/`vivaldi.exe`/
  `firefox.exe`）才算浏览器，**认不出就跳过**继续往下找。
- 桌面壳 `Progman` / `WorkerW` / `Shell_TrayWnd` 也要排除。

## 测试端点前缀陷阱（再踩）

`tests/conftest.py` 把 `RPA_EXT_ENDPOINT_PREFIX` 设为 `rpacore-iso_`（隔离用）。
契约测试里**写死** `rpa_core_ext_msedge_xxx` 会让 `_endpoint_browser` 解析不出浏览器段
⇒ `_target_matches_instance` 也不认 ⇒ 退回全部端点 ⇒ 「只发 Edge」的判据**恒假**（假绿）。
修法：加 `endpoint_for(browser, token)` 帮助函数用 `endpoint_prefix()` 构造端点名。
**教训：凡构造端点名必走 `endpoint_prefix()`，别手写前缀。**

## macOS 调研（本轮不实现）

macOS **有等价机制**，但形态不同：

- `CGWindowListCopyWindowInfo(kCGWindowListOptionOnScreenOnly | kCGWindowListExcludeDesktopElements,
  kCGNullWindowID)` 返回**前到后（front-to-back）**顺序的窗口列表 ⇒ **就是 Z 序**；
  `kCGWindowLayer == 0` 是普通窗口，第一个 layer-0 即当前 Space 最前窗。
  **不需要辅助功能权限**（只有读 `kCGWindowName` 标题才需要屏幕录制权限）；
  `kCGWindowOwnerPID` 可拿进程 → `NSRunningApplication.executableURL` 取进程名（同 Windows 腿思路）。
- `NSWindow.windowNumbersWithOptions(NSWindowNumberListAllSpaces |
  NSWindowNumberListAllApplications)` 亦返回 front-to-back 窗口号（备选）。
- 置前：`NSRunningApplication.activate(options:)` 或 AppleScript `activate`。
- **缺的部分**：**没有直接 API 查询「按最近激活排序的应用列表」**（`NSWorkspace.frontmostApplication`
  只给当前最前应用），要历史序列得自己用 `NSWorkspaceDidActivateApplicationNotification` 维护栈。
  但**对我们的用法不致命**——我们只取「栈顶那个浏览器」，front-to-back 列表本身就给了；
  最前是 Finder 时沿列表往下找第一个浏览器即可，与 Windows 腿算法同构。
  ⚠️ 唯一语义差：Windows Z 序是**完整历史**（能取到「最近激活但现在被压住」的浏览器），
  macOS `OnScreenOnly` 默认不含完全遮挡/最小化的窗口 ⇒ 需去掉该选项取全量自行过滤。
- **接缝已留好**：`_WindowsAPI` Protocol 就是平台抽象落点，加 `_MacWindows` +
  按 `sys.platform == "darwin"` 分派即可；纯逻辑（过滤 + 取第一个浏览器）可原样复用。
  macOS 上 `_default_api()` 恒 None ⇒ 自动退回旧广播语义，**不会崩**。

## 与 M47.7 / M47.8 的关系

三者同源（「该把校验打到哪儿」）但根因各不相同：

| | 管什么 | 谁负责 |
|---|---|---|
| **M47.7** | **同一浏览器内多窗口**时「打到哪一页」 | 扩展侧 `pickVerifyTab` |
| **M47.8** | **跨浏览器**时「谁该闪」 | 扩展侧非前台不闪 + 延后 120ms |
| **M47.9** | **谁是目标浏览器**（不再让浏览器自判） | **host 侧 Z 序定点下发 + 置前** |

M47.9 把「目标」从**猜**（广播 + 各自判前台 + 首个回传者胜）改成**选**（Z 序取，
定点下发）。M47.8 的 `silent` / 延后 120ms 退化为「确实广播时才需要」的兜底，
定点下发后不再是主链路。

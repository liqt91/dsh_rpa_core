## 影刀那一屏的结构（对齐目标）

```
[重新捕获 / 捕获相似元素]        ← 已有（ElementDialog 按钮盒）
[元素名称                ]        ← 已有（name_edit）
[已找到 1 个元素        ]        ← preview_label（命中数唯一落点）
[预览 | 精准定位 | AI]           ← 前两个页签；AI 不摆
  预览  = 页面截图 + 红框         ← PreviewShot（本轮新增）
  精准定位 = DOM树 | 属性表        ← QSplitter（M47.10 已并排）
[锚点            + 添加]          ← 置灰（单独立功能项）
[默认选择器 / XPath] + 帮助/完成/保存并继续   ← XPath 置灰（M51）
```

## 实现

### 扩展侧（截图回传）

- `extension/content.js`（`EXT_BUILD` 0.6.3 → **0.7.0**）
  - `firstHitRect(doc, css)`：首个命中的**视口** rect（`{left,top,width,height}`）。
    为什么是视口坐标而不是文档坐标：截图来自 `captureVisibleTab`，拍的就是**当前
    视口**——红框必须与「截图那一瞬的视口」对齐。
  - `viewportInfo()`：`{width,height,dpr,scrollX,scrollY}`。`dpr` 必带：截图是
    **物理像素**，视口尺寸是 CSS 像素，两者差一个 `devicePixelRatio`。
  - `flashForShot(els)`：画好框 → 等 background 拍完（≈200ms）→ 700ms 后自清。
    **不复用 `preview` 的 persist**：那样框会一直留到下一次预览，用户关掉编辑器才消失。
  - `runVerify(css, mode, silent, keepFlash)`：新第 4 参。`keepFlash===true` 且
    `mode!=="preview"` 时走 `flashForShot`。
- `extension/background.js`（`0.6.3` → **0.7.0**）
  - `runVerify(msg)` 收 `wantShot`；下发信封补 `keepFlash: wantShot`（**补注入重试
    两次都用同一个 `ask`**，否则第二次重试丢掉 keepFlash、拍到空页面）。
  - `captureVisible(tab)`：`chrome.tabs.captureVisibleTab(tab.windowId, {format:"png"})`，
    **吞异常返回 null**——截图是观感增强，拿不到图不该让校验失败。
  - 非前台（`silent`）**不截图**：拍的是别人眼前的窗口，毫无意义。
- `extension/manifest.json`：`version` 0.6.3 → **0.7.0**（三方一致是契约测试钉着的）。

### host 侧（`capture/verify.py`）

- `ElementVerifier.verify(css, *, want_shot=False)`：信封多带 `wantShot`。
  **缺省不截图**：普通「校验元素」每次截一张 base64 PNG 既慢又占内存。
- 透传 `dataUrl` / `rect` / `viewport`；**`dataUrl` 只在 `want_shot` 时透传**
  （没人要的几百 KB base64 不该进 GUI 内存）。
- trace **不落 dataUrl**（会撑爆 `ext-host.log`），只记 `has_data_url` / `bytes` /
  `has_rect`。
- 新纯函数 `preview_box_in_image(rect, viewport, image_size)`：视口 CSS 像素 → 图内像素。
  - **优先用图的实际尺寸**而不是 `dpr`：Windows 分数缩放下图宽与 `round(视口宽×dpr)`
    可能差 1px，而红框偏 1px 在小元素上就是「框没套住」。
  - **刻意不用 `scrollX/scrollY`**：截图拍的就是视口，rect 也是视口坐标——同源，
    加偏移反而把框推到图外。保留字段只为诊断，并由
    `test_preview_box_ignores_scroll_offset` 钉住。
  - 三种「不画框」返回 `None`：无 rect / 零面积 / 形状不对。**绝不画假框**
    （0×0 或负坐标的框会让用户以为「框住了但选不中」而反复折腾）。

### GUI（`gui/element_editor.py`）

- 新增 `PreviewShot(QWidget)`：图 + 红框。**不缩放图**（用户要看「元素在页面哪儿」，
  缩到全图塞进控件细节全看不清）；画框时按「控件宽 / 图宽」再缩一次。
- 新增 `decode_shot(data_url)`：坏 base64 / 非 PNG 一律返回 `None`，**绝不抛**。
- `_build_browser` 重排为：命中标签 → 主选择器（常驻）→ `QTabWidget`
  （「预览」= `PreviewShot`，「精准定位」= 树+表并排）→ 选择器单选 → 锚点行。
- **截图只在切到「预览」页签时触发**（`_on_tab_changed` → `_run_shot`）：
  改 css 的 500ms 防抖不截——用户在精准定位页改选择器时根本不看图。
  截图与驻留预览用**各自独立**的 `seq`（`_shot_seq` / `_preview_seq`）：陈旧的截图
  回传不该作废当前预览的命中数，反之亦然。
- **备选定位 UI 整体移除**：`candidate_list` / `candidates_label` / `promote_button` /
  `_sync_promote` / `_promote` 全部删除；纯函数 `promotable` / `promote_candidate` /
  `_candidate_label` 一并退役（无调用方即死代码）。
  **`selector.candidates` 仍在 `result_document` 里原样带回**——运行期自愈
  （`executors.browser._element_candidates`）按失败 selector 反查它做回退，
  删界面≠删数据。
- 「默认选择器 / XPath」单选：XPath **摆出来但置灰**+ 悬浮说明。全链路只认 css
  （`page_call` 没有 `document.evaluate`），做成能点的就是**假功能**（用户选它、保存、
  运行期静默按 css 走）。实现见 M51，落地后去掉 `setEnabled(False)` 即可。
- 「锚点 + 添加」**整行置灰**：browser 元素的 `selector.anchor` 在模型里没有消费方，
  摆一个能点的「添加」只会写下一个运行期没人读的字段。桌面腿的锚点编辑是**另一个**
  入口（`_build_anchor_view`），那边是真能用的。
- 无 `path` 的老元素：「精准定位」页**说清为什么空**（空白页签会被当成加载失败）。
- 桌面分支**不摆**这两个页签（没有页面可截图、没有 DOM 路径可勾）。
- 接线：`app.py` 两个入口都用 `partial(verifier.verify, want_shot=True)` 传
  `shot_css`——截图与校验必须**同一瞬间**（框要先画好再拍），故不另开方法。

# M47.7：校验取页口径（真前台窗口优先）

Status: `done`

Plan: M47 活体校验通道 / 真机报障「命中数 0/1 抖动」

## 目标

修掉「校验元素」计数抖动的 bug：同一条 css、同一个页面，命中数在 0 与 1 之间跳。
用户口径（原话）：*「实际上在两个页面上都命中了一个，但是只统计可见页面的命中数量
（即 1 个），这个逻辑是对的」*——**只统计可见页是正确行为，问题在「哪一页算可见」不稳**。

## 根因（真机 trace 实锤，不是推断）

`%TEMP%\rpa-capture-trace.log`（2026-10-08 17:28–17:31）里同一条 css 的 verify 回复：

| 时刻 | count | url |
|---|---|---|
| 17:28:47 | **0** | `xiaohongshu.com/explore/6ac7175…` |
| 17:28:54 | **1** | `xiaohongshu.com/search_result_ai?keyword=…` |
| 17:28:59 | **0** | `xiaohongshu.com/explore/6ac7175…` |
| 17:29:04 | **1** | `xiaohongshu.com/search_result_ai?keyword=…` |

**计数抖动其实是「打到了哪一页」在抖**——count 0 的回复全部来自 explore 页、
count 1 的全部来自 search_result 页，两页交替。

原因：`background.js` 的 `runVerify` 用
`chrome.tabs.query({ active: true, lastFocusedWindow: true })[0]` 取页。
`lastFocusedWindow` 是**窗口**级的「最近聚焦」记忆，Chrome 整体失去前台
（GUI 模态对话框抢走 OS 焦点 / 切到别的应用）时它**不会失效**，仍指向上一次聚焦
的那个浏览器窗口；开了多个浏览器窗口时，它就在窗口之间来回指。

旁证：同一次会话 `arm_progress` 报 `tabs: 1`（arm 时只有一个标签页），
之后第二个 tab 才出现——「打开了多个页面」与 trace 一致。

## 设计要点

- **顺序三选一**（新纯函数 `pickVerifyTab()`，独立切片锚点 `[verify-target:start/end]`）：
  1. **真前台窗口的活跃页**（`windows.getAll()` 里 `focused:true` 的窗口 → `tabs.query({active:true, windowId})`）
     —— Chrome 在前台时这就是用户眼前那页，**准**；
  2. 最近聚焦窗口的活跃页（旧行为，Chrome 不在前台时的**近似**兜底）；
  3. 任一活跃页（极端兜底，如只剩无窗口的标签页）。
- **不许把稳定性换成永远失败**：兜底链必须保留——「Chrome 整体不在前台」不得退化成
  `no-active-tab`（W7 钉住）。
- **取页失败不得变成校验失败**：`windows` API 抛错要走兜底链（W8 钉住）。
- **可切片的纯函数**是判据能下沉到 node 门禁的前提（项目既有口径：JS 语义一律 node 切片）。
- **EXT_BUILD 0.6.1 → 0.6.2**（三方：background / content / manifest）。
  **改扩展码必须重载扩展**——Load unpacked 是「载入即快照」，不重载则真机跑的仍是旧码，
  修复看起来无效（这是 2026-09-29「修复无效」事故的根因）。

## 教训

- **探针首版两处自伤**（都是「验证没打中」的变体）：
  ① 哨兵用了 `#`——`#` 在 JS 里是语法错误，注入把 node 切片打成语法异常，门禁
  `new Function` 抛异常后 `process.exit(1)` **且不打印「N 项失败」**，探针只数汇总行 →
  把「确实红了」误判成绿。**修法：哨兵按目标文件的注释语法取（JS 用 `//`）**，
  且失败判据以**退出码 + 期望文本**为准，不依赖汇总行。
  ② pytest 判据多传了一个 `-q`，与 `pyproject.toml` 的 `addopts = "-q"` 叠加成 `-qq`
  —— `-qq` 会连汇总行（`1 failed, 2 passed`）一起吞掉。**修法：不重复传 `-q`**。

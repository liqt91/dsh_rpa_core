# M47.8：双浏览器「都闪框」修复（非前台不应答）

Status: `done`

Plan: M47 活体校验通道 / 真机报障「两个浏览器都高亮」

## 目标

修掉「Chrome 与 Edge 同开同样页面时，校验元素**两个页面都闪黄框**」的 bug。
维护者口径：*「影刀是哪个窗口被激活，就高亮这个窗口中的匹配元素……我们的统计结果是
对的，也是显示匹配 1 个，但在两个页面都高亮了」*。

## 根因（本机实测，非推断）

`host` 侧 `ElementVerifier._exchange` 把 `capture_verify` **广播给全部在线端点**：

```python
candidates = [self._endpoint] if self._endpoint else list_extension_endpoints()
for name in candidates:
    ...
    channels.append(local_transport.connect(name, timeout=2.0))
```

而**端点 = 一个浏览器实例**。本机实测：

```
在线端点数: 2
 - rpa_core_ext_chrome_f540da8e230216fc
 - rpa_core_ext_msedge_33738899c67a8455
```

⇒ Chrome 与 Edge **各收到一次**校验请求，**两个浏览器的页面都闪黄框**。

**为什么统计仍是 1**：`verify.py::read_loop` 只认**首个回传**——
`if not isinstance(message, dict) or "reply" in box: continue`，`box["reply"]` 一旦写入，
后到者被丢弃。所以命中数 = 先回应的那个浏览器的值（两页都命中 1，故恰好对）。
这正是维护者观察到的「统计对、框错」的不对称。

## 设计要点

- **把「是否前台」交给浏览器自判**（这是只有浏览器自己知道的事实）：
  `chrome.windows.getLastFocused().focused` 在浏览器整体失焦给另一个浏览器/应用时为
  false，正是需要的语义（与既有 `focusedState()` 同源）。
- **非前台 ⇒ 不闪框**：background 给 content 的信封加 `silent`，content 收到
  `silent:true` 时只回 count、**绝不画框**。
- **非前台 ⇒ 延后应答**（`VERIFY_BACKGROUND_ANSWER_DELAY_MS = 120`）：把「首个应答」
  让给前台那个浏览器（host 认首个回传），从而**统计与高亮双双锁定「用户眼前那个」**。
- **两条不许踩的线**：
  ① **fail-open**——`getLastFocused` 抛错/无窗口时当作前台（宁可多闪一个框，也不能让
     「判不出前台」变成「谁也不应答、host 等满 5s 超时」）；
  ② **不假超时**——两个浏览器都不在前台（用户切到别的应用）时，各自延后 120ms 后
     仍以 `silent:true` 应答 ⇒ 不闪框、**计数照常有值**（等价旧行为）。
  120ms 远小于 host 的 5s 硬超时。
- **延后期间可转前台**：延后结束后**再判一次**，用户切回来了就走正常路径（照常闪框）。
- **EXT_BUILD 0.6.2 → 0.6.3**（三方一致）。**改扩展码必须重载扩展**。

## 与 M47.7 的关系

同源不同因，两个独立缺陷：
- **M47.7** 管的是**同一浏览器内多窗口**时「打到哪一页」（`lastFocusedWindow` 失准）；
- **M47.8** 管的是**跨浏览器**时「谁该闪」（host 广播到全部端点）。

M47.7 的 `pickVerifyTab` 只能让每个浏览器各自选对自己的页；它管不了「两个浏览器都闪」。

# M1.2 副作用契约

状态：`done`

## 目标

明确描述命令对外部世界产生的副作用，使重试、恢复和人工处置都不会错误假设所有 action 可以安全重放。

## 任务

- [x] 定义副作用类别：`pure`、`read`、`idempotent-write`、`unsafe-write`、`session`。
- [x] 在 command manifest 中加入重放策略和幂等性元数据。
- [x] 将松散的 `CommandResult.effects` 升级为类型化副作用记录。
- [x] 定义副作用生命周期状态：`prepared`、`committed`、`failed`、`unknown`。
- [x] 定义不安全重试配置在 compiler 和 runtime 中的处理方式。
- [x] 增加 manifest、模型、runtime 和 executor 契约测试。
- [x] 编写 ADR 0002，固定重放和幂等语义。

## 验收标准

- [x] 每个 stable command 都声明副作用类型和重放策略。
- [x] Compiler 和 Runtime 都拒绝不安全的自动重试配置。
- [x] 副作用记录包含稳定标识、资源和执行结果。
- [x] 浏览器和 Python worker 垂直切片生成有效的副作用证据。
- [x] 完整 harness 门禁通过。

## 范围外

- 持久化检查点的具体实现。
- 分布式事务或 exactly-once 承诺。
- 自动补偿工作流。

## 已确定决策

- 副作用 policy 分为 `kind`、`replay` 和 `idempotency` 三个独立维度，避免把副作用性质与重放能力混为一谈。
- `pure/read` 使用 `replay=safe`；`idempotent-write` 使用 `replay=idempotent`；`unsafe-write/session` 使用 `replay=unsafe`。
- `read` effect 也持久化，因为它是实际执行证据，不只是 manifest 推导信息。
- `data.writeJson` 使用规范化输出路径派生 idempotency key，但当前仍保持 `retryable=false`，不因具备幂等描述就自动开启重试。
- `browser.navigate` 保守分类为 `unsafe-write`，因为导航可能通过 GET 或重定向触发服务端副作用。
- 成功的非 `pure` 命令必须返回与 manifest kind 一致的 `committed` effect，否则 Runtime 返回 `INVALID_OUTPUT`。
- 失败结果中的 `failed/unknown` effect 必须进入 `stepFailed` 和最终错误 details，禁止丢失外部结果不确定性。

## 完成证据

- 9 个 stable manifest 全部声明合法 effect policy，architecture checker 将 `effect` 设为必填字段。
- `EffectRecord` 使用 `runId + stepId + attempt + index + kind + resource` 派生 64 位十六进制 `effectId`；同一 attempt 稳定，不同 attempt 不同。
- Compiler 和 Runtime 双层拒绝 `replay=unsafe` 且 `retry_count > 0` 的 workflow。
- 浏览器 8 个操作和 Python worker 写文件在真实 Chromium E2E 中产生类型化 committed effect。
- 测试覆盖矛盾 policy、缺失成功证据、unknown 失败证据保留、幂等键和 unsafe retry 拒绝。
- 30 项测试、Ruff、架构检查、任务一致性检查和完整 harness 门禁全部通过。

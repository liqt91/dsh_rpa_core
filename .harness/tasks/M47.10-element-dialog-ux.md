## ②「备选定位」盘查结论（**关键，决定了不改代码**）

维护者反馈：*「我这几次捕捉都没看到有备选定位，感觉这个功能的实现基础不牢固。」*
——**观察正确**，但根因不是「功能没用」，而是**候选生成面太窄**：

- 生成侧 `extension/content.js::candidatesFor` **只推** `#id` 与 7 个属性的
  `[name="…"]` 形式：`data-testid / data-test / data-qa / name / aria-label /
  placeholder / title`；
- 而主 css 由 `pathEntryFor` 生成（`#id`，或 `tag.class[0]` + `:nth-of-type`）；
- 现代前端（React / Vue）组件普遍**既无 id 也无那 7 个属性** ⇒ `candidatesFor`
  返回空 ⇒ 候选列表恒空 ⇒ **运行期自愈（M28）实际永不生效**。

⇒ 正确的做法是**让候选真的有东西**（把候选生成对齐主 css 的 class 路径，例如同时推
`tag.classCombination`、`[class*=]`、属性组合等），**而不是**把候选区折叠/删掉。
这是一个跨扩展 + 契约 + 执行器 + 自愈的改动，与 ⑤ XPath 同属「定位方案供给面扩容」，
合并立片（M51）。**本轮不动代码**——先让事实正确（本轮只在任务单与 memory 里留证据）。

## ③ 文案去重

此前两处「命中 X 个」：

1. 确认框自己的 `verify_label`：`捕获时命中 X 个`（**静态旧值**，捕获那一刻的）；
2. 编辑区预览标签：`预览：命中 X 个`（**实时**）。

两者语义重叠，且用户改了 css 后**会互相矛盾**（旧值不再成立但还挂在那）。
修法：**只留编辑区那条**（它是实时的、随 css 变化刷新），并去掉「预览：」前缀
（来源已在场景里体现，标签不必再自称「预览」）。desktop 元素没有活体通道
（编辑区预览标签不出现），此时才保留确认框自己的静态命中数。

## ④ 主选择器输入框

主选择器是祖先链拼出来的（`body > div.wrap > button.ok:nth-of-type(2) > span`），
在 560px 宽的对话框里一行装不下，`QLineEdit` 会把尾巴截掉。
修法：新增 `SelectorEdit(QPlainTextEdit)`——**多行 + 随内容自适应高度**（1~4 行），
换行显示不截断、不需要横向滚动；对外保留 `text()` / `setText()` **同名 API**，
让替换是**就地**的（调用点二十来处不用动，落盘口径仍唯一 `self.css_edit`）。

## 踩坑：`SelectorEdit` 的信号遮蔽（**本片最大教训**）

初版写成：

```python
class SelectorEdit(QPlainTextEdit):
    textChanged = Signal(str)          # ← 盖住 QPlainTextEdit 原生 textChanged
    def __init__(...):
        ...
        super().textChanged.connect(self._on_text_changed)   # ← 解析到子类那个
```

想借它对外提供 `QLineEdit` 的 `textChanged(str)` 语义。结果：

- `super().textChanged` 在 Python **MRO** 下仍解析到**子类那个从未 emit 的**信号
  ⇒ `.connect` 连上去永远不触发 ⇒ `setText` 之后界面毫无反应
  （`test_editor_browser_blocks_blank_css` 直接红：`assert '不能为空' in ''`）；
- `QPlainTextEdit.textChanged` 还是 `Signal` **descriptor**，想直接 `.connect`
  原生信号会 `AttributeError: 'Signal' object has no attribute 'connect'`。

实测确证：

```
text= '   ' emitted= []                 # setText 后，子类信号没发
after setPlainText text= 'xx' emitted= []   # 原生也走不通（被盖住）
```

**修法**：不遮蔽——让原生 `textChanged` **保持可用**（调用方连它即等价
`QLineEdit.textChanged` 的能力：无参信号 + 读 `.text()`），高度重排另外挂在
`document().contentsChanged`（编辑器唯一的「文本变了」真源，`setPlainText` 与键入都走它）。
修复后实测 `setText`/`setPlainText` 都 emit。

> **教训**：Qt 子类**不要用同名类属性遮蔽原生信号**——`super().X` 在 Python 里
> 解析的是**类型属性**（子类覆盖优先），C++ 侧的「父类实现」拿不到。

# ADR 0010：编辑器宿主形态 —— 保持 Web 页面，桌面客户端后置

- 状态：已接受
- 日期：2026-09-03
- 关联：ADR 0008（编辑器 UI 放行与零构建形态）、ADR 0007（dev server）、`docs/capture-browserskill.md`（bsk 路线）、M14 任务单
- 维护者提问：捕获元素时编辑器最好隐藏、不遮挡屏幕——编辑器做成桌面客户端是否更好？

## 背景

捕获元素时，编辑器窗口若遮挡屏幕上的目标会影响捕获。维护者提出桌面客户端（pywebview/Tauri 类薄壳）可以程序化隐藏/最小化窗口、支持全局热键唤起捕获，是更贴合 RPA 工具形态的选择（Power Automate Desktop / UiPath 均为桌面应用）。

## 遮挡场景实证分析

| 捕获场景 | 编辑器是否遮挡目标 | 机制 |
|---|---|---|
| bsk 浏览器捕获（M14 主路线） | 不遮挡 | 目标在独立 Agent Window，编辑器在用户普通浏览器窗口（2026-09-03 实机验收实测） |
| 桌面捕获带 `windowHandle` | 不遮挡 | M10 窗口作用域 hit-test 枚举目标窗口自身控件，免疫覆盖层（原为防安全软件遮罩设计） |
| 桌面捕获前台窗口模式 | 不遮挡 | 用户点击目标窗口置前，编辑器退后台 |
| 桌面捕获裸屏幕 hit-test | **会遮挡** | 编辑器盖屏时命中的是编辑器自身——唯一真实缺口，但裸屏幕路径本身是兜底（优先级最低） |

结论：主流捕获路径已被现有设计绕开；遮挡只在兜底路径发生。

## 决策

1. **编辑器保持 web 页面**（ADR 0008 维持不变）：dev server 托管的零构建 vanilla 单页，设计期工具定位不变。
2. **补齐真实缺口不靠客户端**：桌面裸屏幕捕获的遮挡问题，用"捕获前先 attach 目标窗口拿 `windowHandle`"解决（窗口作用域命中天然免疫遮挡）——并入 M14 元素库「＋捕获」入口的 desktop 分支设计（编辑器上加"选择目标窗口"步骤）。
3. **桌面客户端薄壳列为后置项**，进入 `.harness/tasks/BACKLOG.md` 远期，触发下列条件之一即立项重估：
   - 裸屏幕桌面捕获成为高频设计期动作；
   - 需要全局热键唤起捕获（web 页面沙盒做不到）；
   - M15（WorkBuddy 连接器）之后用户画像确认为非开发者用户为主力（届时 CLI+Skill 已覆盖另一通道，桌面客户端成为第三界面需重新权衡双份投入）。

## 排除确认

桌面客户端的打包/安装器需求触碰 `project_state.json` scope.out 的 `installer` 排除项；本 ADR 决定在该排除解除前不引入任何桌面壳依赖（pywebview/Electron/Tauri 均暂缓）。

## 后果

- 编辑器演进继续在零构建边界内进行（ADR 0008 §2 硬边界不变）。
- M14 元素库「＋捕获」入口的 desktop 分支必须含"选择目标窗口"步骤（attach → windowHandle 作用域捕获）。
- 桌面客户端重估条件书面化，避免日后重复讨论。

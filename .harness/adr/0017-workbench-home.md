# ADR 0017：宿主形态三 —— 工作台（首页）+ 编辑器两段式

- 状态：**已接受（2026-09-20）**
- 日期：2026-09-20
- 关联：ADR 0016（GUI 为唯一主力形态）、ADR 0014（编辑器宿主形态二 —— 方案 E 原生 PySide6）、
  ADR 0011（GUI/编辑器不承载 runtime）、M25（运行历史只读读取器）、M27（本决策的落地里程碑）
- 目的：把「流程管理」与「流程编辑」拆成两个界面，对齐影刀的使用心智；同时明确多窗口编辑器的边界。

## 1. 背景

GUI 自 ADR 0016 起是唯一主力形态，但**流程管理**一直是工具栏上的一个下拉框
（`flow_combo`），**运行历史**是编辑器底部的一条 dock。两者都是「浏览/管理」类任务，
却被塞进「编辑单个流程」的界面里：

- 流程一多，下拉框无法呈现状态（最近运行成功/失败、最近运行时间、元素资产数量）；
- 运行历史 dock 只能看当前上下文，无法全局浏览、按流程筛选；
- 影刀的心智是**两段式**：首页（应用列表：新建/导入/最近运行状态/运行记录）→ 双击进入编辑器。

后端能力早已具备，缺的只是宿主形态：流程列表与读取（`WorkflowDirStore.list/read`）、
运行历史（`rpa_core.run_history`，M25）都不需要新增持久化格式。

## 2. 决策

**采用两段式宿主：独立「工作台」窗口（首页）+ 现有编辑器窗口。**

1. **工作台是独立窗口**（`rpa-core gui` 默认打开它；影刀式首页），承载：
   - **流程列表**：名称、最近运行状态/时间、元素资产数量、修改时间；支持新建、打开、复制、
     重命名、删除、导入/导出；
   - **运行历史**：全局视图（可按流程筛选），双击一条历史 → 在编辑器打开该流程并载入时间线；
   - **运行入口**：可对流程发起运行并查看状态（运行/暂停/继续的**控制权仍在编辑器**，见第 3 条）。
2. **编辑器仍是单窗口**（现有 `MainWindow` 不变：画布 + 参数面板 + 运行/元素库/数据表格/
   变量 dock）；从工作台双击流程打开编辑器，编辑器内保留「流程库」下拉用于快速切换。
3. **运行控制归属编辑器**：工作台只提供「运行 + 看状态」；暂停/继续/单步只在编辑器
   （避免两处都能控制同一个 run 造成状态分叉）。两个入口共用同一 `run_artifacts`，天然一致。
4. **删除流程 = 提示后连同其资产一并删除**（`<流程>/workflow.json`、`elements/`、`data/`）
   与**该流程的运行历史**（按 `workflowId` 匹配的 `run_artifacts/*`）；提示文案必须列出
   将删除的资产数量，默认按钮为「取消」。
5. **多窗口编辑器（每流程一窗）不在本期**：牵动窗口生命周期、`RunManager` 归属、脏数据
   关闭确认与整套 GUI 测试基线，收益（并行编辑）未验证；待工作台用起来后再单独评估。

## 3. 后果

**正面**

- 「管理流程」与「编辑流程」各得其所：流程多、历史长时可扩展（列表/筛选/状态），不再依赖下拉框；
- 与影刀心智一致，降低迁移成本；
- 后端零改动：复用既有 store 与 run_history 能力层，不引入新持久化格式（AGENTS 规则 10）。

**代价 / 约束**

- 新增一个窗口与一套生命周期（工作台 ↔ 编辑器打开/关闭/刷新联动）：需要明确「编辑器保存后
  工作台刷新」「删除流程时编辑器正在编辑该流程」等边界；
- GUI 测试基线从「单一 `MainWindow`」扩展为「工作台 + 编辑器」，既有合同测试保持不变，
  新能力补工作台侧测试；
- 运行控制两处入口的分工必须写进文档，避免用户以为工作台能暂停。

## 4. 被否备选

- **保持现状（下拉框 + dock）**：治标不治本，流程/历史一多即不可用。
- **多窗口编辑器（每个流程一个窗口）**：见决策第 5 条，成本高、收益未验证，推迟。
- **把工作台做成单窗口内的「首页」页签**：省一个窗口，但编辑器与首页共享同一窗口会互相
  挤占（画布/停靠面板与列表视图差异大），且与影刀的两段式不符；独立窗口更干净。

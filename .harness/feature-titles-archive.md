```
M60: a ddddocr-based captcha recognition command family, cut into the same manifest-driven shape as the other 87 commands (S1 delivers ocr.recognize; detect and slideMatch follow). ddddocr is a C extension wrapping onnxruntime with a global singleton model whose authors say not to re-initialise it, and its import (1.11s) plus first construction (0.13s) plus first inference (0.44s) is a one-time cost of about 1.7s, so the library runs in a RESIDENT worker subprocess (workers/ocr_worker.py, one JSON per line over stdin/stdout) rather than in the orchestrating process - resident rather than python_worker's one-process-per-command, which drops every later recognition to about 0.01s. The executor (executors/ocr.py) owns only the subprocess lifecycle and the response-to-CommandResult mapping, and races the round-trip against the cancellation event, because awaiting it directly would swallow a cancel that arrives during a seconds-long first inference; cancelling discards and rebuilds the process since the request may already be mid-inference. probability=True additionally returns a per-charset probability matrix (measured at several MB for a single 64x26 image) and a thousands-entry charset table; neither is ever passed through, so result.json cannot be inflated, and a judgement pins the serialised result under 4096 bytes. ## `selector-advisor`（原文 3803 字符）
```

```
Rank locator/selector candidates by a uniqueness gate then a penalty table, so capture picks the most stable one. The engine is a shared pure function (model.desktop.choose_best_locator / locator_penalty): a lexicographic (count, penalty) order makes uniqueness the hard gate (a count==1 candidate always beats any penalty), ties keep input order for determinism, and a data-driven penalty table (semantic labels and fixed ids low, position indices and runtime handles high) encodes stability priors; ids that look framework-generated are demoted. capture_at consumes it via _pick_best_candidate. Penalties are priors to be calibrated on real machines, so the contract only pins that the table is read and composed, not its values. S2 extends the same engine to the browser leg: the shared sorter now lives in model.selector_ranking.rank_candidates (model.desktop.choose_best_locator delegates to it, and looks_generated_id moved there so both legs demote framework-generated ids with one predicate); browser candidates get their own prior table (kind plus attribute-name breakdown, and an unmeasured matchedCount sorts last), and executors.browser._element_candidates returns the ranked order so runtime self-healing retries candidates most-stable-first without any extension-side change. S3 persists the fully scored candidate list at capture time (desktop capture_at writes selector.candidates = each candidate's locator, matchedCount, and penalty; the browser host scores content-script candidates with web_candidate_penalty) and the GUI capture-confirm dialog lists them read-only for debugging. Desktop candidates need no contract change (_candidate_errors only validates browser selectors) and rank_web_candidates ignores them (they carry no selector string), so both legs share one key without interfering.
```
